# 联网搜索回退链与代理出口（2026-10-16）

## 问题

用户反馈「联网功能不可用」。实测：

- 选中 GPT 但 GPT 未连接时，`selectSearch` 仍无条件走 GPT 搜索并直接报错「GPT 搜索不可用」，不会尝试已连接的 StepSearch 或无凭据公共搜索。
- GPT 搜索对部分中文查询（如「上海今天天气」）返回 0 条来源，也不会换路。
- 无凭据 Exa 只能直连；只能经 HTTP 代理出网的环境（公司网络、只开系统代理的桌面代理软件）搜不到。
- 整条搜索 20 秒总时限，GPT 搜索实测 9–23 秒，慢时被截断。
- 未连接任何模型时，「最近有什么AI新闻」这类自然提问直接回「未连接模型」，只有「搜索…/查一下…」前缀才会联网。

## 现在的行为

| 场景 | 顺序 |
| --- | --- |
| 选中 GPT | GPT 搜索（仅已连接）→ StepSearch（有 Plan Key 时）→ 公共搜索 |
| 选中 StepFun | StepSearch（有 Key 时）→ GPT 搜索（已连接时）→ 公共搜索 |
| 没有任何账号 | 公共搜索 |

- 任一路返回来源即结束；出错或 0 条继续下一路；全部为空时如实返回空列表，全部失败时提示依次尝试过哪些路径。
- 结果来自非所选路径时，提示写「GPT 搜索不可用，已改用公共搜索，整理了 3 条结果」，来源卡 `provider` 也如实记录。
- 每路有独立时限（GPT 30s / StepSearch 20s / 公共搜索 25s），整链 50s，留在 90s 意图预算内；卡住的一路不会拖垮后续回退。调用方取消、模型连接变更立即终止，不再回退。
- 无凭据搜索只发送查询，不带 GPT 令牌或 Plan Key（测试断言）。
- 未连接模型时，明显是查资料的问题（新闻/最新/价格/行情/是什么/有什么……）直接走搜索；涉及卡片、提醒、画布操作或含多步指令的不会被误当搜索。

## 代理出口

公共搜索端点固定为 `mcp.exa.ai`，可经代理：

- `VIVIC_SEARCH_PROXY`：未设或 `auto` = 依次读 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量、操作系统代理（Windows 注册表 / macOS `scutil --proxy`；Linux 桌面经环境变量）；`direct` 关闭；其他值视为代理 URL。系统代理 30 秒重读，开关代理软件无需重启。
- 先走代理（15 秒上限），代理失败再走原有固定公网 IP 直连（含 fake-IP 时的 DoH 兜底）。
- **网页正文读取（`/api/fetch`、读取链接）不使用该代理**：代理会自行解析域名，绕过逐跳公网地址校验，因此仍只直连。
- OpenAI 出口的 `VIVIC_OPENAI_PROXY` 同样补上了 macOS 系统代理读取。

## 验证

- `pnpm --filter @vivic/local-api test`：948 通过；2 项 `wire-json-schema` 失败为本机 `core.autocrlf=true` 检出 CRLF 所致，与本改动无关（文件内容逐字节差异仅为行尾）。新增 `tests/search-fallback.test.ts` 13 项，覆盖排序、跳过未连接 GPT、空结果换路、全失败提示、单路超时与整链超时、取消/切换不回退、代理失败转直连、网页读取不走代理、代理配置解析、macOS 代理解析。
- `pnpm --filter @vivic/web test`：405 通过；三个包 typecheck 通过。
- 本机实测（5176/8789，后端热重载后 GPT/StepFun 均未连接）：
  - `/api/search`「上海今天天气」：此前 GPT 返回 0 条；现由公共搜索返回国家气象中心等来源，约 5 秒。
  - 公共搜索三种出口：系统代理 2.2s、直连（DoH 兜底）5.5s、失效代理 `127.0.0.1:1` 自动转直连 2.5s，均 5 条来源。
  - 意图：「搜索 上海迪士尼门票价格」「帮我查一下今天A股收盘情况」「OpenAI 最新发布了什么」均生成来源卡；「帮我梳理这段项目思路」仍提示未连接模型，不误搜。

## 限制

- 公共搜索是 Exa 免费额度，短时间大量查询会返回「免费额度暂时受限」，约一分钟后恢复。连接 GPT 或 StepFun 后它只作最后兜底。
- 跨付费路径回退（GPT ↔ StepSearch）会消耗另一账号的额度，但提示中会写明。
- 网页正文读取仍只能直连；只能经代理出网的环境读不到正文，但搜索来源卡可用。
